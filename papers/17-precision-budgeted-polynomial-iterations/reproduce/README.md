# Reproduction archive — Precision-Budgeted Polynomial Iterations

Sources, measurement scripts and the JSON results of the paper
*Precision-Budgeted Polynomial Iterations: Sensitivity Certificates and Subspace Error Floors*
(single author).

## Contents

| path | what it is |
|---|---|
| `scripts/pilot*.py` | one script per experiment; each writes one `*_results.json` |
| `results/*_results.json` | the JSON each script produced; every number in the paper is a field of one of these files |
| `logs/*_run.log` | the printed report of the scripts that print one |
| `pilot11_momentum.npz` | the Muon momentum sequence (500 matrices) measured in §6.2; regenerated by `pilot11_momentum_subspace.py` |
| `pilot21_momenta.npz` | the 80 momentum matrices of the five-layer `digits` run used in §6.5 and §6.6 (per-matrix figures in `results/pilot21b_kmin.json`); regenerated by `pilot21_loss_phase_and_scheduler.py --stage b1` |
| `paper/` | the LaTeX sources (`main.tex`, `sections/*.tex`, `references.bib`), the figures (`figures/*.tex`, vector `pgfplots`; their coordinates in `figures/data/*.dat`), the three static checkers and the standalone builder |
| `scripts/pilot25b_seed_level.py` | reads `pilot25_results.json` and reports the same census per seed: run rates with Clopper--Pearson intervals, a bootstrap that resamples seeds, and the seed-level tests of the census appendix |
| `scripts/make_figure_data.py` | writes `paper/figures/data/*.dat` from the result JSONs; this is the only place a plotted coordinate is produced |
| `paper/validate.py` | static check of the text: environments, braces, references, labels, table cells, word count |
| `paper/validate_figures.py` | static check of the figures: plot files exist and have the columns each plot names, no orphan `.dat`, every figure `\input` with a caption and a label |
| `paper/pagebudget.py` | the page estimate of the body (words, floats and the rates used) |
| `paper/make_standalone.py` | builds the single self-contained `.tex` (figure coordinates and bibliography carried inline) from `paper/main.tex` and the sections |
| `run_all.sh` | runs every script in the order the tables were produced, then the static checks |
| `MANIFEST.sha256` | SHA-256 of every experiment file (scripts, results, logs, the `.npz` files, `run_all.sh`, this file) |
| `MANIFEST-paper.sha256` | SHA-256 of the paper sources and `validate.py` |

## Running it

    ./run_all.sh

Pure `python3` with `numpy`, `scipy` and `scikit-learn`; no GPU, no dataset download (the
last script loads `sklearn.datasets.load_digits` and `load_diabetes`, which ship with the
package). Run here on Python 3.12.16, numpy 2.5.4, scipy 1.18.1, scikit-learn 1.9.1, one
CPU core: the whole sequence takes about 70 minutes; `pilot19` takes 52 seconds,
`pilot20` 108, `pilot21` about 100 and `pilot25` about 40 minutes on one core (it takes
`--workers`, and `run_all.sh` uses two).  `pilot25b` runs no new training: it reads
`pilot25`'s runs and takes a few seconds.

`pilot25_long_census.py` is the long census of §6.6: 1,200 training steps × 25 seeds ×
three conditions × two tasks is 150 runs and about 4.5 million Muon calls.  It is
resumable (`--task`, `--cond`, `--seeds`, `--workers`) and writes no wall-clock field, so
`results/pilot25_results.json` is a function of the seeds and reproduces byte for byte;
`--analyse` recomputes the census, the block hazards, the tests and the prefix check
against `pilot23` and rewrites the JSON in place.  A 1,200-step run restricted to its
first 400 steps is the 400-step run of `pilot23`, which is how the two censuses are one
experiment (24 of 24 comparable runs agree).

Each script writes its JSON next to itself, i.e. into `scripts/`.  Running the sequence
therefore regenerates the outputs in place and leaves `results/` untouched, which is what
makes the two comparable: `sha256sum -c MANIFEST.sha256` passes on a fresh extraction, and
re-running `pilot19_large_d_and_decomp.py`, `pilot20_analytic_and_d1024.py` or
`pilot21_loss_phase_and_scheduler.py` reproduces `results/pilot19_results.json`,
`results/pilot20_results.json` and, stage by stage, `results/pilot21_results.json`.
`pilot20` reads `pilot19_results.json` for the d ≤ 512 curve it extrapolates and for
the pooled d = 512 reference: next to itself when `pilot19` has just run in the same
directory, otherwise from `../results/`.  `pilot21` and `pilot23` resume from an existing
`pilot21_results.json` / `pilot23_results.json` in their directory, so delete that file
before re-running in `scripts/` if the point is to test the reproduction.

`pilot22_participation_factor.py` (about four minutes) reproduces
`results/pilot22_results.json` byte for byte.  `pilot24_large_d_multiplicity.py` (about
five minutes) reproduces `results/pilot24_results.json` field for field; it reads
`pilot22_results.json` from `../results/` when it is not next to itself.  `pilot23_divergence_mechanism.py` (about
seven minutes across the nine stage invocations of `run_all.sh`) reproduces every measured
field of `results/pilot23_results.json`; the only difference is the wall-clock `seconds`
field each run records.  One caveat about that script: the step at which a run diverges is
sensitive to the last bits of the arithmetic, so an implementation that differs from this
one in a side computation can move a divergence from step 24 to step 73 while keeping the
census (which runs diverge, and under which condition) identical.  The paper quotes the
census and one instrumented trace, not the step counts.  All random draws use
`numpy.random.RandomState` with an explicit seed, so a run is deterministic on a given
numpy version.

## What is not here

The landscape scripts (`analyze*.py`, `pick.py`, `arxiv_search.py`, `or_reviews.py`) are
not part of any claim in the paper; they read the ICLR submission dumps (several hundred
MB), which are not redistributed.  `paper/validate.py` and `paper/validate_figures.py`
are static checks of the sources (environment balance, references, labels, table column
counts, word count; and the figures against their data tables) and need no TeX
installation; neither is a compile.
